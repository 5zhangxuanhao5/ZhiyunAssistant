# Windows 验证范围

此页区分迁移检查、当前主机检查与 Windows 原生验证；不是“所有电脑均无故障”的承诺。

## 已有证据

- 原鸿蒙行为基线用于迁移核对，Windows 继承了适合桌面执行的纯模型与服务回归；ArkUI 字符串断言不被当作 Windows UI 验收。
- 当前 macOS 主机可执行 TypeScript 检查、Node 服务测试和原生 Electron 窗口回归。界面场景使用明确的合成账号和课程；媒体样本由视频/音频发生器生成，不包含真实课堂内容。
- 原生 Electron 媒体检查可验证 MP4/HLS 解码、时间推进、寻址、倍速及控件几何，但不能据此声称真实校园视频或 Windows 硬件路径已经通过。
- PE 架构、ASAR 资源、后台图像 Worker、运行时完整性及敏感文件审计属于发布包静态检查。

完整的本机最终结果必须与最后一次构建对应，以该提交的测试记录为准。此前单独通过的用例不被写成未运行的最终整套结果。

## 2026-10-13 本机收尾检查

- TypeScript 检查和 240 项模型、服务及桌面单元检查通过，零失败、零跳过。
- 31 项 Electron 界面场景整套通过；最后的 AI 时间范围修复之后，相关问答、笔记与真实媒体场景另复测 16 项，全部通过。
- 新增了慢速读取学习进度、读取完成前退出、无视频阅读时点、录像长短与课表不一致的检查。视频在首次解码前恢复保存进度；时间跳转按实际录像范围而非课表裁短。
- 本页问法另有实际 AiClient 的合成请求检查：读取模式允许本页现有讲解，播放模式以真实提问时点为界；当前页图像按需读取，工具请求不默认扩大到整节课。检查没有使用真实校园资料或付费 API。
- 本机为 macOS Apple Silicon，以上不扩写为 Windows 用户硬件、官方校园认证或真实教室媒体已全部验收。

## Windows CI 门禁

仓库工作流在 Windows x64 和 ARM64 分别执行：

1. npm ci、类型检查、行为单元与 Electron 窗口回归。
2. 生成对应架构的 NSIS 安装包和 ZIP。
3. 核对 PE 架构、必需运行资源与 ASAR 中的隐私边界。
4. 安装到中文含空格目录，启动安装后的 EXE，检查启动与卸载。
5. 保留测试报告，两个架构都成功后才允许工作流上传预发布包。

实际运行结果见 [GitHub Actions](https://github.com/He-He-He-He-He-He/ZhiyunAssistant/actions)。工作流配置存在不等于已经成功运行；报告必须引用对应提交与运行。x64 的 Windows Server 运行器不能证明每个 Windows 10/11 桌面设备的兼容性。

## 仍需现场验证

干净 Windows 普通用户账户、真实校园认证及权限变化、各种教室视频编码与直播历史、Windows 安全存储、显卡硬件解码、实体键鼠/触控板/触摸屏、中文 IME、不同 DPI 与多屏、弱网和休眠恢复，以及大量离线课程并发管理的长期稳定性。

付费 AI 验证需要用户自己的有效密钥与同意的调用范围。不得把合成响应、协议桩或构建成功当作真实 API 调用成功。
